Server Recovery Procedures

Category: Infrastructure

This document contains critical procedures for bare-metal recovery of the primary production database clusters. These steps must only be executed by Level 3 infrastructure engineers during a verified Sev-1 incident.

01 Phase 1: Initial Assessment

Step 1: Access the master node via the out-of-band management console (iLO/iDRAC). Do not attempt SSH if the primary network interface is unresponsive.

Step 2: Verify the integrity of the encrypted storage volumes before attempting to mount. Run the pre-flight checksum script located in the secure bastion environment.

$ ssh -i ~/.ssh/recovery_ed25519 admin@bastion-01.internal
$ sudo /opt/recovery/verify_luks_headers.sh /dev/nvme1n1

02 Phase 2: Decryption & Mounting

Step 3: Decrypt volume using the vault-injected ephemeral token. The token is valid for 15 minutes post-generation.

$ cryptsetup luksOpen /dev/nvme1n1 cryptdata --key-file=/dev/shm/ephemeral_token.key
$ mount /dev/mapper/cryptdata /mnt/recovery_target
warning
Critical Warning Failure to cleanly unmount and close the LUKS container after recovery will trigger an automatic hardware quarantine protocol upon reboot.

03 Phase 3: Service Restoration

Step 4: Validate database consistency via the internal toolset. Check logs for WAL corruption.

Step 5: Initiate the master promotion script and update DNS routing tables to point to the newly restored active node.
